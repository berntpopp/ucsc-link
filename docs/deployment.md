# Deployment

## Docker

The image ships no data and keeps no on-disk state: every tool calls the live UCSC JSON API
and responses are cached in-process only (TTL). The production overlays run it with a
read-only root filesystem and a tmpfs; no volume is needed.

```bash
# Local dev (loopback-published, builds from source)
make docker-build && make docker-up && make docker-url

# Production (nginx-proxy-manager overlay, pulls the released digest)
UCSC_LINK_IMAGE=ghcr.io/berntpopp/ucsc-link@sha256:<digest> \
  docker compose -f docker/docker-compose.npm.yml --env-file .env.docker up -d
curl -fsS -H 'Host: localhost' http://127.0.0.1:8000/health
# → {"status": "ok", "version": "...", "capabilities_version": "..."}
```

## Fleet deploy contract

`docker/docker-compose.npm.yml` is the Compose file the GeneFoundry fleet controller
(`strato_v6_docker_npm`) deploys and validates. It declares `user: "10001:10001"` --
this image's own numeric uid:gid, read from `docker/Dockerfile`'s
`groupadd --gid 10001 app && useradd --uid 10001 --gid app ...`; the controller's
runtime observer proves the effective uid from `/proc`, so the declared value must
be numeric, not the account name. `user` must NOT appear in `docker/docker-compose.yml`
or `docker/docker-compose.prod.yml` -- those are the Compose files listed in
`container-release.json`, and the shared release gate (`container_release.py
validate-compose`) forbids `user` on them. `tests/unit/test_deploy_overlay_user.py` guards
both halves of this contract.

`container-release.json` also declares `service.deployed_compose_files:
["docker/docker-compose.npm.yml"]` -- the exact file the controller deploys.
Both reusable-workflow pins (`.github/workflows/container-ci.yml`,
`.github/workflows/container-release.yml`) must track the same
`genefoundry-router` revision (`tests/test_workflow_pins.py`): the shared
`_container-release.yml` workflow runs `container_release.py
validate-deployed-overlay` against the declared file before every release,
and `_container-ci.yml` loads the same `ReleaseConfig` schema from its own
pin to validate this JSON, so an older pin there rejects new fields.

Release checklist: bump `pyproject.toml` `version`, run `uv lock`, add a
`CHANGELOG.md` heading `## [x.y.z] - YYYY-MM-DD`, bump `CITATION.cff` `version:`
(generated by `make citation-write` in genefoundry-router) -- tag `vx.y.z`, then approve
the `release` GitHub Environment gate (it can fire more than once) via `gh api
repos/berntpopp/ucsc-link/actions/runs/<id>/pending_deployments`
(`status: waiting` is the gate).

Self-check that the controller can render and project this overlay:

```bash
UCSC_LINK_IMAGE="ghcr.io/berntpopp/ucsc-link@sha256:<64 hex>" docker compose -f docker/docker-compose.npm.yml config --format json > /tmp/r.json
# from strato_v6_docker_npm: uv run python -c "import sys,json; sys.path.insert(0,'scripts'); from utils.deployment_preflight import canonical_projection; canonical_projection(json.load(open('/tmp/r.json')), project='ucsc-link'); print('PROJECTION OK')"
```

## Configuration (environment variables)

All settings use the `UCSC_LINK_` prefix; nested models use `__` as the delimiter.
Copy `.env.docker.example` to `.env.docker` and set the values for your deployment.

### Server settings

| Variable | Default | Purpose |
|----------|---------|---------|
| `UCSC_LINK_HOST` | `0.0.0.0` | Bind host (use `127.0.0.1` behind a reverse proxy). |
| `UCSC_LINK_PORT` | `8000` | Bind port. |
| `UCSC_LINK_TRANSPORT` | `unified` | `unified` \| `http` \| `stdio`. |
| `UCSC_LINK_MCP_PATH` | `/mcp` | MCP endpoint mount path (must start with `/`). |
| `UCSC_LINK_ALLOWED_HOSTS` | `["localhost","127.0.0.1","::1"]` | Exact HTTP Host allowlist as JSON; wildcards are rejected. |
| `UCSC_LINK_ALLOWED_ORIGINS` | `[]` | Exact browser Origin allowlist as JSON. |
| `UCSC_LINK_CORS_ORIGINS` | `""` | Comma-separated allowed CORS origins. |
| `UCSC_LINK_LOG_LEVEL` | `INFO` | `DEBUG`…`CRITICAL`. Logs go to stderr. |
| `UCSC_LINK_LOG_FORMAT` | `console` | `console` (dev) \| `json` (prod). |

Browser deployments must configure the same exact origins in
`UCSC_LINK_ALLOWED_ORIGINS` and `UCSC_LINK_CORS_ORIGINS`; the strict
transport guard and browser CORS are independent controls.

### UCSC upstream (`UCSC_LINK_UCSC__*`)

| Variable | Default | Purpose |
|----------|---------|---------|
| `UCSC_LINK_UCSC__BASE_URL` | `https://api.genome.ucsc.edu` | UCSC JSON API base URL (only this origin is ever contacted). |
| `UCSC_LINK_UCSC__REQUEST_TIMEOUT_S` | `20.0` | Per-request timeout. |
| `UCSC_LINK_UCSC__MIN_INTERVAL_S` | `1.0` | Process-wide spacing between upstream requests. `15` = strict Conditions-of-Use reading. |
| `UCSC_LINK_UCSC__DAILY_CAP` | `5000` | Upstream requests per UTC day; beyond it tools answer `rate_limited`. |
| `UCSC_LINK_UCSC__MAX_WAIT_S` | `20.0` | Longest queue wait for a request slot before answering `rate_limited` with `retry_after_s`. |
| `UCSC_LINK_UCSC__MAX_RETRIES` | `2` | Retries on 429/5xx/timeouts (exponential backoff, honours `Retry-After`). |
| `UCSC_LINK_UCSC__BACKOFF_BASE_S` | `2.0` | Backoff base (seconds). |
| `UCSC_LINK_UCSC__MAX_RESPONSE_BYTES` | `16777216` | Hard cap on one upstream body (fail closed). |
| `UCSC_LINK_UCSC__CACHE_TTL_S` | `3600` | In-process response cache TTL. |
| `UCSC_LINK_UCSC__CACHE_MAXSIZE` | `512` | In-process response cache entries. |

**Why 1/s and not 1 per 15 s.** UCSC's API help recommends at most one hit per second ("no
strict limit"); its general Conditions of Use limit program-driven use to one hit every 15
seconds and 5,000 per day. A 15 s spacing makes a multi-step agent question take minutes, so
the default follows the API-specific guidance while keeping the 5,000/day cap. The limiter is
per process: run one replica, or divide the budget between replicas.

### Live integration checks

`make test-integration` makes a handful of real calls through the same limiter (opt-in, never
in CI).

## Transports

Three transports, selected with `--transport` or `UCSC_LINK_TRANSPORT`.

| Transport | Serves | MCP endpoint? |
|-----------|--------|---------------|
| `unified` (default) | FastAPI `/health` + MCP `/mcp` on one port | **yes** — `/mcp` |
| `http` | FastAPI/REST **only** | **NO** |
| `stdio` | MCP over stdin/stdout (Claude Desktop) | yes (stdio framing) |

> **Footgun.** `--transport http` is REST/FastAPI-only: it does **not** mount the MCP app, so
> there is no `/mcp` endpoint. An MCP client (or the GeneFoundry router) pointed at an `http`
> server will fail to connect. Use `unified` for MCP over HTTP.

In `unified` mode the server mounts the MCP Streamable-HTTP ASGI app alongside the FastAPI
application on one port:

```
:8000
  GET  /health   → FastAPI health endpoint (capabilities_version, status)
  *    /mcp      → FastMCP Streamable-HTTP (all 6 tools, ucsc:// resources)
```

This is the transport the GeneFoundry router uses — it proxies the `/mcp` endpoint as
`https://ucsc-link.genefoundry.org/mcp`.

## MCP client configuration

**HTTP (Streamable HTTP).** Start the server in `unified` mode, then register the `/mcp` URL:

```bash
uv run ucsc-link                    # unified, :8000
claude mcp add --transport http ucsc-link --scope user http://127.0.0.1:8000/mcp
```

**Stdio** (Claude Desktop / Claude Code). Uses the dedicated `ucsc-link-mcp` entry point;
stdout is reserved for the protocol, so logs go to stderr only:

```json
{
  "mcpServers": {
    "ucsc-link": {
      "command": "uv",
      "args": ["run", "ucsc-link-mcp"],
      "cwd": "/path/to/ucsc-link"
    }
  }
}
```

## GeneFoundry router registration

`servers.yaml` entry (router side):

```yaml
  - name: ucsc
    repo: berntpopp/ucsc-link
    url_env: GF_UCSC_URL
    namespace: ucsc
    entrypoints: [search_genome, get_region_annotations]
```

with `GF_UCSC_URL=https://ucsc-link.genefoundry.org/mcp`.
